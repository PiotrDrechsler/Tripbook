# Tech Stack

Poniżej opisujemy zestaw technologii wybranych dla projektu Tripbook oraz krótkie uzasadnienie wyboru:

---

## 1. Astro 5

- Lekki framework do budowy stron hybrydowych (SSG + “island architecture”).
- Generuje statyczne pliki dla większości widoków, co przyspiesza ładowanie i obniża koszty hostingu.
- Pozwala włączać interaktywne komponenty React tylko tam, gdzie są potrzebne.

## 2. React 19

- Sprawdzone narzędzie do budowy dynamicznych interfejsów użytkownika.
- Dzięki integracji z Astro “wyspy” React pozwalają dodać modal, panele boczne i listy wycieczek bez pełnego SPA.
- Ogromny ekosystem, łatwość zarządzania stanem i szeroka społeczność.

## 3. TypeScript 5

- Statyczne typowanie minimalizuje błędy podczas developmentu i przyspiesza refaktoryzację.
- Ułatwia współpracę w zespole – każdy komponent i każda funkcja mają jednoznacznie zdefiniowane kontrakty.
- Dobrze integruje się zarówno z Astro, jak i z Reactem.

## 4. Tailwind 4 + Shadcn/ui

- Tailwind: narzędzie utility-first do szybkiego stylowania bez pisania CSS od zera.
- Shadcn/ui: biblioteka gotowych, responsywnych komponentów UI (formularze, modale, przyciski) kompatybilna z Tailwind.
- Zapewniają spójność i szybkość budowy interfejsu (PRD §3.4).

## 5. Supabase (BaaS)

- Dostarcza autoryzację z email/hasłem, bazę Postgres, RLS (Row-Level Security), REST/GraphQL i real-time.
- Umożliwia szybkie wdrożenie backendu bez pisania serwera: rejestracja, logowanie, CRUD dla tras (PRD §3.1, §3.2).
- Automatyczna skalowalność w chmurze, darmowy plan startowy, prosty w integracji z frontendem.

---

### Krótkie podsumowanie

- **Szybkość MVP**: Astro + Supabase + gotowe UI = minimalny kod “boilerplate”.
- **Skalowalność**: statyczne pliki + zarządzany backend → niski koszt przy małym ruchu, możliwość rozbudowy.
- **Bezpieczeństwo**: TypeScript + RLS w Supabase + walidacja po stronie serwera i klienta.
- **Utrzymanie**: popularne, dobrze udokumentowane narzędzia, duża społeczność i ekosystem.
- **Elastyczność**: łatwo dodać nowe funkcje (np. osadzanie mapy w iframe, testy E2E, CI/CD).

> Ten stack pozwoli nam sprawnie dostarczyć MVP Tripbook, zachowując kontrolę nad kosztami, bezpieczeństwem i możliwościami rozwoju.
